# dixsu-туннель: подключение и автобэкап

Подробная документация по функции dixsu-туннеля этого форка: подключение к устройству за
CGNAT/NAT через [dix.su](https://dix.su), просмотр файлов через системный файловый менеджер и
автоматический бэкап (например, фото) через сторонние приложения синхронизации.

## Что такое dixsu-туннель

Устройство, находящееся за CGNAT/NAT (обычный домашний интернет, мобильная сеть), физически
недоступно снаружи напрямую по SSH/SFTP. dix.su держит постоянный туннель до такого устройства и
проксирует подключения через `<slug>.dix.su:2222`, где `slug` — уникальное имя устройства.

Протокол простой: клиент подключается обычным TCP-сокетом на `<slug>.dix.su:2222`, отправляет
строку `DIXSU:<slug>\n`, после чего сокет становится обычным SSH/SFTP-соединением до реального
устройства. Это приложение делает это автоматически — руками ничего слать не нужно.

## Настройка SFTP-соединения через dixsu

1. Добавь новое соединение → **Storage: SSH FTP (Apache Commons)**.
2. Включи тумблер **«dixsu tunnel»**.
3. В появившемся поле **Slug** укажи имя устройства на dix.su (то, что до `.dix.su` в его адресе).
   Host/Port подставятся и заблокируются автоматически (`<slug>.dix.su:2222`).
4. «Do not check SSH trusted hosts» включается автоматически — так и должно быть: проверка ключа
   хоста иначе шла бы против локального конца туннеля, а не против реального устройства.
5. Заполни обычные User/Password (или ключ) — это учётные данные самого устройства, к dix.su
   как сервису отношения не имеют.
6. **Check connection** (иконка папки со стрелкой вверху) — должно пройти успешно.
7. **Save**.

## Просмотр файлов

Приложение само по себе не имеет файлового браузера — оно регистрируется в системе как
[DocumentsProvider](https://developer.android.com/guide/topics/providers/document-provider), и
через него подключение видно в любом файловом менеджере, поддерживающем SAF (Storage Access
Framework): Total Commander (через плагин `content`/SAF в списке File system plugins → системный
пикер → CIFS Documents Provider → выбрать папку → постоянный доступ), X-plore, Material Files,
стандартный «Файлы» и т.д.

## Локальный SFTP-прокси (для автобэкапа и других приложений)

SAF — это просто способ, которым другие приложения видят хранилище, а не протокол передачи данных
сам по себе. У SAF нет своих механизмов фонового пуш-синка (как у Google Photos) — чтобы получить
автоматический бэкап фото, нужно либо стороннее приложение-синхронизатор, работающее через SAF,
либо (что обычно быстрее и надёжнее) — напрямую по SFTP, в обход SAF.

Для этого в форме SFTP-соединения с включённым dixsu tunnel есть секция **«Local SFTP proxy»**:

- Кнопка **«Start proxy»** поднимает локальный TCP-порт `127.0.0.1:<port>` на телефоне. Любое
  приложение, умеющее подключаться по обычному SFTP, может подключиться к этому адресу с теми же
  логином/паролем, что указаны в самом соединении — преамбулу dixsu оно отправит наше приложение,
  дальше это неотличимо от обычного SFTP-сервера.
- Порт **детерминированный** — вычисляется из внутреннего ID соединения и не меняется между
  запусками прокси. Один раз настроил в стороннем приложении — адрес остаётся рабочим.
- Кнопка **«Copy address»** копирует `127.0.0.1:<port>` в буфer обмена.
- Прокси держится в фоне (постоянное уведомление), переживает сворачивание приложения. Кнопка
  **«Stop proxy»** останавливает.

### Обязательный шаг — отключить оптимизацию батареи

Если приложение не исключено из оптимизации батареи, рано или поздно Android (особенно на не-stock
прошивках вроде MIUI) заморозит/убьёт фоновый процесс, и прокси перестанет отвечать — со стороны
это выглядит как «прокси постоянно падает», хотя само приложение не крашится, просто система не
даёт ему работать в фоне.

Если это разрешение ещё не выдано, в той же секции появится предупреждение с кнопкой
**«Disable battery optimization»** — тап открывает системный диалог «Let app always run in
background?». После **Allow** предупреждение пропадает автоматически.

## Настройка автоматического бэкапа фото через FolderSync

Полный процесс — от адреса прокси до расписания синхронизации.

**Шаг 0.** В приложении: открой нужное соединение → **Start proxy** → скопируй адрес кнопкой
**Copy address** (например, `127.0.0.1:42495` — у каждого соединения свой порт).

**Шаг 1 — Account (подключение) в FolderSync:**
1. **Accounts** → **+** → тип **SFTP**.
2. **Server** — `127.0.0.1`.
3. **Port** — число, скопированное на шаге 0 (НЕ 22/2222 — именно локальный порт прокси).
4. **Username** / **Password** — те же, что в самом SFTP-соединении в приложении.
5. **Test connection** — обязательно проверить (в момент проверки в приложении должно быть видно
   «Proxy running»).
6. Сохранить Account.

**Шаг 2 — Folderpair (что с чем синхронить):**
1. **Folderpairs** → **+** → выбрать созданный Account.
2. **Local folder** — например `DCIM/Camera`.
3. **Remote folder** — путь на удалённом устройстве (браузер откроется через тот же прокси).
4. **Sync type** — **Local to Remote** (для бэкапа, не наоборот).
5. **Schedule** — по таймеру или **Instant Sync** (сразу при новом файле, расходует больше батареи).
6. Сохранить.

## Диагностика проблем

| Симптом | Причина | Решение |
|---|---|---|
| Прокси постоянно «падает» / FolderSync теряет соединение | Android/OEM убивает фоновый процесс без разрешения на неограниченную работу в фоне | Кнопка **«Disable battery optimization»** в секции прокси → Allow |
| FolderSync: Test connection не проходит | Прокси не запущен, или скопирован не тот порт | Открой приложение, убедись что видно «Proxy running: 127.0.0.1:XXXXX», используй именно этот порт |
| После переустановки/нового соединения адрес другой | Порт зависит от ID соединения — новое соединение = новый ID = новый порт | Это ожидаемо для нового соединения; для одного и того же сохранённого соединения порт не меняется |
| В файловом менеджере не видно подключения | Менеджер не поддерживает SAF/DocumentsProvider | Использовать SAF-совместимый менеджер (Total Commander с content-плагином, X-plore, Material Files) |
