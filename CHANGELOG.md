# Changelog

Форк [wa2c/cifs-documents-provider](https://github.com/wa2c/cifs-documents-provider), базовая версия Ver.2.4.0(31).

## [v2.4.0-dixsu.14] — 2026-10-21

### Исправлено
- **SSH keepalive для SFTP**: NAT и dixsu-туннель молча обрывали простаивающее SFTP-соединение, после чего следующая операция висела до таймаута. Теперь при простое JSch шлёт keepalive каждый раз, когда истекает таймаут сессии (10 с), и разрывает соединение с ошибкой после 3 keepalive подряд без ответа — вместо вечного зависания.

## [v2.4.0-dixsu.13] — 2026-10-21

### Исправлено
- **ANR при «Sync now» на медленных SFTP-хостах** (например, WD My Cloud со старым sshd через dixsu-туннель): приложение зависало, и Android показывал диалог «CIFS Documents Provider isn't responding». Причина: `SendRepository.sendUri`, `sendUriSkippingExisting` и `sendFolderSkippingExisting` выполняли блокирующие вызовы (`existsFile`, рекурсивный обход папки `collectFilesRecursively`) прямо на главном потоке. На быстрых хостах это занимало миллисекунды, а на медленных — секунды на каждый файл, и через 5 с срабатывал ANR. Теперь эти операции идут на IO-диспетчере.

## [v2.4.0-dixsu.12] — 2026-08-29

### Добавлено
- **Автобэкап в фоне** (режим 2 — второй, автономный режим бэкапа): чекбокс **«Auto backup (sync in background)»** в секции Backup (появляется вместе с выбранной локальной папкой). Периодически (раз в ~15 минут — минимальный интервал, разрешённый Android для `PeriodicWorkRequest`, короче в принципе невозможен) проверяет папку на новые файлы и грузит их тем же путём, что и «Sync now», но не требует, чтобы приложение было открыто.
  - Планируется/отменяется при нажатии **Save** в зависимости от состояния чекбокса — как и с прокси, действует именно факт сохранения, а не сам чекбокс.
  - В отличие от локального прокси, не нужен `DixsuAutoStartWorker`-подобный перезапуск при старте процесса — периодическая задача `WorkManager` сама сохраняется между перезапусками процесса. Как и у прокси, не переживает полную перезагрузку телефона без единого запуска приложения (нет `RECEIVE_BOOT_COMPLETED`, см. прокси).
  - Только ставит файлы в очередь — саму загрузку (с уведомлением и прогрессом) выполняет уже существующий `SendWorker`, тот же самый, что и у «Sync now» и share-интентов.

## [v2.4.0-dixsu.11] — 2026-08-29

### Добавлено
- В экране выбора удалённой папки («Folder» в настройках соединения — та же папка, куда «Sync now» загружает бэкап) теперь есть кнопка **«New folder»**: создаёт подпапку прямо внутри текущей просматриваемой директории на удалённом хосте (в том числе через dixsu-туннель) и сразу переходит в неё. Раньше можно было только выбирать уже существующие папки.

## [v2.4.0-dixsu.10] — 2026-08-29

### Исправлено
- Новое SFTP-соединение с включённым по умолчанию (см. dixsu.9) чекбоксом «dixsu tunnel» не могло подключиться: диалог «the configured ssh destination has been connected for the first time... trust and connect?» → «Connection failed». Причина: включение галочки «dixsu tunnel» через сам чекбокс попутно выставляло `ignoreKnownHosts = true` (проверка ключа хоста иначе идёт против локального конца туннеля, а не реального устройства), но когда галочка уже стоит по умолчанию при создании соединения, этот код никогда не срабатывал, и `ignoreKnownHosts` оставался `false`. Теперь host-key checking принудительно отключается на уровне подключения (`ApacheSftpClient`) для любого dixsu-tunnel соединения независимо от сохранённого флага — не зависит от того, через чекбокс или через дефолт включён туннель.
- Чекбокс «Do not check SSH trusted hosts» в форме соединения теперь визуально отображается включённым и заблокированным, пока включён dixsu tunnel — раньше выглядел выключенным, хотя проверка ключа хоста для туннеля всё равно не применяется.

## [v2.4.0-dixsu.9] — 2026-08-28

### Исправлено
- Чекбокс **«dixsu tunnel»** в форме нового соединения теперь включён по умолчанию — вместе с дефолтным типом хранилища SSH FTP это основной сценарий использования приложения.
- «Sync now» останавливался после первого файла в очереди, если при его отправке возникала ошибка (например, сетевой сбой) — исключение из `SendRepository.send()` пробрасывалось наружу и убивало `SendWorker` целиком, остальные файлы навсегда оставались в статусе «Ready». Теперь ошибка одного файла помечает только его как `FAILURE` и логируется, а очередь продолжает обрабатывать остальные файлы.

## [v2.4.0-dixsu.8.1] — 2026-08-28

### Исправлено
- Новое соединение по умолчанию создаётся с типом хранилища **SSH FTP (Apache Commons)** вместо SMB2/3 — это основной протокол dixsu-туннеля, не нужно переключать вручную при каждом новом соединении.

## [v2.4.0-dixsu.8] — 2026-08-28

### Добавлено
- Тумблер **«dixsu tunnel»** в форме SFTP-соединения. При включении:
  - вместо Host/Port — поле **Slug** (имя устройства на dix.su);
  - адрес подключения (`<slug>.dix.su:2222`) подставляется автоматически, поля Host/Port блокируются;
  - «Do not check SSH trusted hosts» включается по умолчанию (проверка ключа хоста иначе идёт против локального конца туннеля, а не реального устройства).
- Приложение само устанавливает TCP-соединение к `<slug>.dix.su:2222`, отправляет преамбулу `DIXSU:<slug>\n` и дальше работает как обычный SFTP — никаких дополнительных действий на устройстве не требуется.
- **Локальный SFTP-прокси** для dixsu-туннеля: чекбокс «Keep proxy running (auto-restart if stopped)» в форме SFTP-соединения (при включённом dixsu tunnel) поднимает `127.0.0.1:<port>` — сторонние приложения (бэкап/синхронизация, например FolderSync/Autosync) могут подключаться к нему напрямую по обычному SFTP с теми же логином/паролем, минуя файловый браузер этого приложения. Работает в фоне через WorkManager + постоянное уведомление, переживает сворачивание приложения. Снятие галочки останавливает.
  - Порт детерминированный (вычисляется из ID соединения), а не случайный — остаётся одним и тем же между запусками прокси, поэтому один раз настроенный в стороннем приложении (FolderSync и т.п.) адрес не «протухает».
  - Если приложение не исключено из оптимизации батареи, Android может убить фоновый процесс с прокси (особенно на не-stock прошивках) — в форме соединения теперь показывается предупреждение с кнопкой «Disable battery optimization», открывающей системный диалог `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`.
  - Состояние чекбокса персистится в самом соединении (`autoStartDixsuProxy`). При каждом запуске процесса приложения (`App.onCreate`) новый `DixsuAutoStartWorker` проходит по всем соединениям с включённым флагом и переподнимает для них прокси — не нужно вручную заходить в настройки после того, как Android убил фоновый процесс. Не переживает полную перезагрузку телефона без единого запуска приложения (для этого нужен отдельный `RECEIVE_BOOT_COMPLETED`-ресивер, которого в манифесте сознательно нет).
  - Адрес прокси (`127.0.0.1:<port>`) теперь виден в форме соединения **всегда**, как только указан Slug — не только когда чекбокс включён и запуск подтверждён асинхронной проверкой через WorkManager. Порт детерминированный (чистая функция от ID соединения), поэтому его можно показать сразу, без гонки с фактическим стартом прокси — раньше при переоткрытии экрана соединения адрес мог пропасть даже когда прокси реально работал в фоне (проверка через `WorkManager.getWorkInfosForUniqueWorkFlow` была лишней и создавала гонку, а не сообщала актуальное состояние вовремя).
- **Бэкап при открытом приложении** — новая секция «Backup» в форме соединения: «Select folder to back up» (обычный системный SAF-пикер) → «Sync now» загружает все новые (по имени) файлы из выбранной локальной папки в корень соединения. В отличие от прокси, ничего не работает в фоне — только пока экран реально открыт, поэтому не подвержено ограничениям Android на фоновые процессы вообще. Уже загруженные файлы (существующие на удалённой стороне) пропускаются автоматически, без диалога подтверждения перезаписи. Переиспользует существующий пайплайн передачи файлов (`SendRepository`/`SendWorker`/`SendNotification`) — прогресс и уведомления те же, что и у ручного «Поделиться → сохранить в это приложение».
  - Первый шаг двухрежимного бэкапа (обсуждение: ручной синк при открытом приложении — надёжно, но не автоматически; фоновый прокси — best-effort, но работает без участия пользователя). Второй режим (нативный фоновый автобэкап без FolderSync) — следующим шагом.
  - Примечание: Android блокирует выбор некоторых папок верхнего уровня (например, `Download`) через системный пикер «To protect your privacy, choose another folder» — это ограничение ОС, не приложения; для фото используйте `DCIM/Camera` или любую вложенную папку.
  - «Sync now» теперь обходит выбранную папку **рекурсивно**, зеркалируя подпапки на удалённой стороне (`DocumentFileManager.collectFilesRecursively`), а не только файлы верхнего уровня.

### Исправлено
- Листинг директорий через dixsu-туннель мог показывать один и тот же файл повторно вместо реального содержимого папки (коллизия document ID из-за расхождения между адресом подключения и адресом соединения). Теперь листинг корректно отражает реальное содержимое.

### Технически
- Реализовано через локальный loopback TCP-форвардер (`DixsuTunnelForwarder`) — аналог `ssh -L`, но внутри приложения: SFTP-бэкенд (Apache Commons VFS + JSch) ничего не знает о туннеле, просто подключается к `127.0.0.1:<port>`.
- Локальный прокси (`DixsuProxyManager`) — отдельный реестр форвардеров, независимый от `DixsuTunnelManager`: последний привязан к жизненному циклу VFS-сессии и закрывается вместе с ней, а прокси должен продолжать работать в фоне независимо от файлового браузера.
- Фон держится через `CoroutineWorker` (`DixsuProxyWorker`) + `setForeground()`, по образцу существующего `ProviderWorker` — без новых `Service`/разрешений в манифесте, используется уже объявленный `FOREGROUND_SERVICE_DATA_SYNC`.
- Без новых зависимостей — только `java.net`/`androidx.work` из уже используемых.
- Затронуты модули: `common`, `data:storage:interfaces`, `data:storage:apache`, `data:storage:manager`, `domain`, `presentation`.
